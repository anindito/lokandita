# Decisions

Technical choices made during the build, newest first. One line each: date, decision, reason.

- 2026-11-17 — Meetings are never deleted, only switched off ("used for practice"), and number and language are locked once a meeting has problems — problems were validated against that language and that place in the concept order.
- 2026-11-17 — A meeting is visible to whoever sees its course but its page answers 403 to a pengajar who is not the pengampu (404 outside the course) — the same three-way answer as changing a class in stage 6.
- 2026-11-17 — Stage 8 texts live in their own language file `Soal.php` (`id`, `en`, `ar`) — `Kode.php` already has 264 lines.
- 2026-11-17 — The judge worker writes `problem_instances` itself and a `GENERATE` result carries no test — a student who creates a job can read its result through `/api/executions/{id}`, so tests must never pass through `judge_jobs`.
- 2026-11-17 — A problem belongs to one meeting (`problems.meeting_id`, slug unique there); `meeting_problems` holds the one approved version in use and is created at the first approval — `KONTRAK.md` §7 imports one file per meeting and identifies a problem by slug within it.
- 2026-11-17 — Translations, `params`, detected concepts and required concepts of a version are JSON columns of `problem_versions` — they are always read and written together with the version and never queried by field.
- 2026-11-17 — The concept catalogue is loaded by the migration from `apps/lokakode/app/Data/konsep.json` (45 concepts, names in three languages) — data, as `SPEC.md` §9 asks, and present on every schema without a separate seeding step.
- 2026-11-17 — Owner's decisions for stage 8: `params` object for `{{param}}`; Markdown statements with raw HTML disabled; `"machine": true` on a translation; no problem-bank access for a pengajar in this stage; a minimal `meetings` table now, the rest of §6 in stage 9; sample files for `DDP101`.
- 2026-11-17 — `infra/tes-infra.sh` section I no longer assumes the other hosts are in maintenance: each of `lokakode` and `portal` must answer by its own flag (503 closed, 200 open) and must answer the same before and after auth is opened. The test never closes a host that is open, so on a server where auth is open the "closed again" assertion does not run — that is the whole difference between the 54 and 55 counted in stages 5–7 (now 57 and 58).
- 2026-11-16 — `judge/uji-terima.sh` is the owner's gate for stage 7: it runs the acceptance tests of `SPEC.md` §10 through `infra/tes.sh judge` (real hostile programs, test schema) and prints one line per item — the gate is the same code as the automated tests, so the two cannot disagree.
- 2026-11-16 — The test for a compile that exhausts memory accepts `memory` or `timeout` as the reason: normally the memory limit stops it in about 3 s, but once in a full run the compiler slowed down near the limit and the 10 s watchdog fired first; the cause of that one slow run was not found. Either way the compile is stopped.
- 2026-11-16 — `GET /api/executions/{id}` answers the same 404 to everybody but the creator, superadmin included, and never returns the payload — `KONTRAK.md` §6 says a user reads only their own jobs; staff will read submissions through their own pages in stage 9, with the policy layer.
- 2026-11-16 — `infra/tes.sh lokakode` starts a real judge worker on the host (schema `lokakode_test`, Redis DB 15) for the duration of the tests — the LokaKode tests send real jobs through MySQL and Redis and read the result over HTTP; if Docker or the judge images are missing the run fails.
- 2026-11-16 — LokaKode has its own small Redis connection inside `App\Libraries\Antrean` instead of sharing LokaAuth's `RedisConn` — fifteen lines, and moving it into the shared package would mean changing and redeploying LokaAuth for no behaviour change.
- 2026-11-16 — Judge containers and job directories carry the worker's instance name (its schema): the production worker and the test worker on this server never see or remove each other's containers — tests can run while students are being judged.
- 2026-11-16 — The worker takes a slot before it pops from Redis, so ids stay in Redis until a thread is free — `normal` is then always served before `low`, also when the worker is busy.
- 2026-11-16 — An unexpected error inside the worker while judging is treated like an infrastructure failure (retried twice, then `judge_unavailable`), with the traceback in the log — a bug of ours must not become a verdict against the student, and must not kill the worker.
- 2026-11-16 — The worker's log is one JSON line per event with job id, kind, verdict and duration; it never contains source code, input, program output or a secret — tested.
- 2026-11-16 — `JUDGE_CONCURRENCY=4` on this 4-vCPU server: 200 queued `RUN` jobs (each one compile container and one run container) finished in 109 s in the test, about 0.55 s per job; other values were not measured.
- 2026-11-16 — `/etc/passwd` and `/etc/group` inside the judge images are mode 600 — the acceptance test of `SPEC.md` §10 demands that a judged program cannot read `/etc/passwd`; it is the image's own file (the host's is not visible at all), and nothing in GCC, NumPy or Matplotlib needs it.
- 2026-11-16 — Judge containers also run with `--ipc none` (no `/dev/shm`) and `--log-driver none` — a flood of output must not be written to Docker's log on the host disk before the 1 MB limit stops it.
- 2026-11-16 — The wall-clock limit (2 × CPU limit + 1 s; compile: 10 s) is enforced twice: by `pelari` inside the container, counted from the moment the program starts, and by the worker from outside 4 s later (allowance for starting a container) — the first is exact, the second does not depend on anything inside the container. The CPU limit is the kernel's `RLIMIT_CPU`.
- 2026-11-16 — Every test of a submission runs in its own new container, about 0.55 s of overhead each on this server — the literal reading of `SPEC.md` §10 and the simplest thing to reason about; reusing one container per submission would be faster and is a change to raise with measurements if queues get long.
- 2026-11-16 — Output comparison `float` accepts a number when the difference is at most ε × max(1, |expected|) — absolute for small values, relative for large ones; `SPEC.md` only gives ε.
- 2026-11-16 — A judge image's tag is the first 12 hex digits of sha256 over everything in `judge/images/`; the worker uses only that tag — an image that does not match the code in the repository can never be used silently, and a missing image fails closed.
- 2026-11-16 — `pelari`, a 150-line static C program, is PID 1 in every judge container: it runs the program, measures CPU and wall time and peak memory inside the container, and prints one report line to stderr prefixed with a random per-run token that it hides from the program (removed from the environment, overwritten in memory, process made non-dumpable) — the student is not charged for container start-up (about 0.55 s here) and cannot forge the report. It is not a security barrier; every limit is still enforced from outside.
- 2026-11-16 — The compiled program leaves the compile container on stdout and the worker writes it to the job directory, which later containers mount read-only — no judge container ever has a writable host directory.
- 2026-11-16 — The seccomp profile is generated by `judge/seccomp/buat-profil.py` from Docker's default (`moby/profiles` tag `seccomp/v0.3.0`, sha256 checked): x86-64 only, capability-dependent rules dropped, `socket` only for `AF_UNIX`, and ptrace, io_uring, keyctl, namespaces, mounts, System V IPC, POSIX message queues and similar removed — the generator and its list are readable; a hand-edited 800-line JSON is not.
- 2026-11-16 — Judge images: `judge-c` and `judge-cpp` are Ubuntu 24.04 (pinned by digest) with its GCC 13 packages; `judge-python` is the official `python:3.12-slim-bookworm` (pinned by digest, Python 3.12.16) with NumPy 2.5.5 and Matplotlib 3.11.2 and their dependencies pinned by hash; Matplotlib's font cache is built into the image and copied to `/box` at start, otherwise every run would spend seconds rebuilding it.
- 2026-11-16 — `DB_PASSWORD_JUDGE` was added to `infra/.env` and `judge/.env` was created on this server by hand (random value, never printed), because `buat-env.sh` refuses to run once any `.env` exists — same as `COOKIE_DOMAIN` in stage 5; a new server gets both from `buat-env.sh`.
- 2026-11-16 — The worker's Python libraries (PyMySQL, redis-py; pytest for tests) are pinned by version and sha256 in `judge/requirements*.txt` and installed into `judge/.venv` by `judge/siapkan-venv.sh` — the host has no pip, and nothing is installed system-wide.
- 2026-11-16 — The worker talks to MySQL over TLS without verifying the certificate — MySQL 8.4 demands an encrypted connection (or an extra crypto library) for password login, the certificate is MySQL's own self-signed one, and the peer is `127.0.0.1`.
- 2026-11-16 — `judge_jobs.created_by` is nullable; `NULL` marks a system job (smoke check) that no user can read — there is no user to name, and inventing a fake user id would be a lie in the table.
- 2026-11-16 — `judge_worker` is created without rights and gets `SELECT, UPDATE` on `judge_jobs` from `infra/mysql-hak-judge.sh`, like `identity_reader` — the worker never inserts or deletes jobs, and the test suite checks that it cannot read the academic tables, the audit log or another schema.
- 2026-11-16 — Owner's decisions for stage 7: the worker runs as a systemd *user* service of `deploy` with linger enabled (restart and verification without sudo); `RUN` works end to end and the other job kinds answer `FAILED` with `unsupported_kind` until stages 8–9 bring their tables; a time limit is CPU time measured inside the container, with a wall-clock kill from outside at 2 × limit + 1 s.
- 2026-11-16 — The new-year tool copies only classes that are not archived, with their name, capacity and pengajar, in one transaction with archiving the old year and activating the new one; like enrollment it is two requests without stored state, and the second validates everything again.
- 2026-11-16 — The roster is one form whose buttons carry their own target (`formaction`); its first submit button is disabled and hidden, so pressing Enter in the date field submits nothing — no JavaScript is needed and no action can be triggered by accident. A "select all" box is added by the shared script; without it each row can still be ticked.
- 2026-11-16 — Resetting a student's password is two requests (a confirmation page, then the reset) and is allowed to whoever may see the class, for students `AKTIF` in that class only; the temporary password is rendered once in the response, never stored or logged in LokaKode — a mis-click during practice would otherwise log a student out.
- 2026-11-16 — Whole-class graduation is the same request as graduating selected students with `semua=1`; it touches only `AKTIF` rows and never overwrites an earlier graduation date. Cancelling returns the row to `AKTIF` and clears the date.
- 2026-11-16 — The target class of a move passes the same check as the source class and must be in the same course and year, not archived; the composite foreign key refuses anything else even if this check were wrong.
- 2026-11-16 — Class capacity only warns in the enrollment preview and never blocks — `SPEC.md` calls it optional and a lecturer must be able to seat one more student; to make it a hard limit is a one-line change the owner can ask for.
- 2026-11-16 — Enrolling a student who withdrew earlier re-activates the same enrollment row (in the class now chosen, with a row in `enrollment_moves` when the class differs); a student already `LULUS` in that course and year is refused and must have the graduation cancelled first — one row per student per course per year, as the schema demands.
- 2026-11-16 — Enrollment is two requests without server-side state: the preview only classifies, the second request carries the nomor induk again and the server classifies them again before saving — what the browser sends back is not trusted, and nothing has to be stored between the steps. Input: free text or `.csv` (first column, comma/semicolon/tab, optional header `nomor_induk`), at most 2000 numbers and 1 MB.
- 2026-11-16 — Deleting a class needs a ticked "Saya yakin" box and is refused with 409 while any enrollment (any status) or class-move record points at it; an archived class stays readable — the CSP forbids an inline confirm dialog, and a checkbox works without JavaScript.
- 2026-11-16 — For a dosen, everything in an archived academic year is read-only (403 with an explanation); the superadmin can still correct it. A pengampu's new class always goes into the active year.
- 2026-11-16 — Changing a class has three answers: 404 when the class is outside what the user may see, 403 when they see it but do not manage it (a pengajar who is not the pengampu), 403 with a reason when the year is archived.
- 2026-11-16 — A new academic year is created archived and becomes active only through "Aktifkan", which archives the current one in the same transaction; there is no separate "archive" button — "exactly one active" then cannot be broken from the UI, and activation is reversible by activating the old year again.
- 2026-11-16 — Course codes are stored upper-case, 2–20 characters of `A–Z`, `0–9` and `-` (so `TS-PY` fits); the pengampu is entered by nomor induk and must be an active `dosen`.
- 2026-11-16 — The shared test for the re-sent session cookie accepts `Max-Age` within 2 seconds of 43200 — the value is computed when the response is sent, so a page that takes longer to build crossed a second boundary and failed the exact match.
- 2026-11-16 — `tests/Policy/MatriksAksesTest.php` reads the registered routes and fails when a route is missing from its authorisation matrix; each route is then requested by six actors (superadmin, two pengampu, two pengajar, a mahasiswa) — a new endpoint cannot ship without an authorisation and cross-class test.
- 2026-11-16 — A class or course outside the user's scope answers 404 with the same page as one that does not exist; a role that may never use a page answers 403 — the number in the URL cannot be used to find out which classes exist.
- 2026-11-16 — The policy layer (`App\Policy\Akses`) returns SQL conditions that `App\Libraries\Akademik` puts into every query; there is no function that loads a class, course or enrollment by id alone — a forgotten check then returns no row instead of someone else's data.
- 2026-11-16 — LokaKode reads names from `user_directory` on every request and keeps no copy; the pengampu and students are looked up there rather than through `/internal/users/lookup` — one source of truth and no HTTP call that can fail while rendering a list.
- 2026-11-16 — LokaKode's `audit_log` has no trigger against UPDATE/DELETE; it is append-only because no code path changes it, as in LokaAuth — creating triggers as `lokakode_app` needs SUPER while binary logging is on.
- 2026-11-16 — An enrollment carries `course_id` and `academic_year_id` next to `class_id`, tied to the class by a composite foreign key — MySQL itself then refuses a second enrollment in the same course and year, and a class move into another course, even if the code is wrong.
- 2026-11-16 — "Exactly one active academic year" is a generated column `satu_aktif` (1 when active, otherwise NULL) with a unique key — MySQL has no partial unique index; the database refuses a second active year.
- 2026-11-16 — Owner's decisions for stage 6: LokaKode keeps its own append-only `audit_log`, written in the same transaction as the change, with a superadmin page; pindah kelas moves the one enrollment row and records the move in `enrollment_moves` (`DIPINDAHKAN` is set by nothing in this stage); pengampu and pengajar can reset a student's password in this stage; a student without `lokakode` access or not `active` is enrolled and flagged, a non-mahasiswa is refused; the new-year tool only warns about students still `AKTIF`.
- 2026-11-15 — Existing pages keep their named component classes (`kartu`, `tombol`, `akun-…`) inside Tailwind's `components` layer instead of being rewritten as long utility strings; utilities and the brand colours (`bg-utama`, `text-teks-redup`, …) are used for new markup — the look stays what the tests and the owner's first browser check will see, and the views stay readable. Tailwind's reset (preflight) is on, so paragraph spacing and list markers are restored in the `base` layer.
- 2026-11-15 — Tailwind CSS 4.3.5 is compiled in a stage of `infra/docker/app.Dockerfile` from the official standalone binary, version pinned and sha256 checked by `ADD --checksum`; the source is `packages/lokandita-auth/gaya/lokandita.css`, the result is served as `/aset/lokandita.css` — owner chose Tailwind (2026-11-15); nothing is downloaded or run on the host, no Node, no CDN. The build fails if the output is empty or still contains uncompiled directives.
- 2026-11-15 — Test helper `Http` returns itself, so a page's CSRF token and import token are read into variables before the next request — two admin tests had read them from a later response; one failed for that reason and one passed for the wrong reason.
- 2026-11-15 — Arabic pages use the locale `ar-u-nu-latn` — digits stay Latin (`SPEC.md` §11) without formatting every number by hand.
- 2026-11-15 — Bulk actions are two requests: the first only counts and names the accounts, the second (with the same list) applies — nothing changes before the superadmin has seen the number.
- 2026-11-15 — CSV and XLSX exports prefix cells that start with `=`, `+`, `-` or `@` with an apostrophe — a student's name must not become a spreadsheet formula on the owner's computer.
- 2026-11-15 — Import limits: 2000 rows per file, CSV (comma or semicolon) or XLSX, columns `nomor_induk, nama, email, global_role, apps`; rows already registered are left untouched, bad rows are listed with their line number and reason — a preview that saves nothing, then one explicit run.
- 2026-11-15 — Random temporary passwords are hashed with a cheaper Argon2id setting (about 40 ms instead of about 300 ms, `Passwords::hashTemporary`) — an import of hundreds of accounts must finish in seconds; safe only because these passwords are random (about 92 bits) and must be changed at first login. Human-chosen passwords, including a shared import password, keep the full cost.
- 2026-11-15 — Temporary passwords and pending import previews live in Redis for 30 minutes, encrypted with `MFA_ENCRYPTION_KEY`, bound to the superadmin who created them (`Brankas`); the password list can be downloaded once, then answers 410 — plaintext passwords never reach MySQL, the audit log or a backup.
- 2026-11-15 — XLSX is read and written with PhpSpreadsheet 5; the app image gains the PHP extensions `zip` and `gd`, and the Composer build step now uses `--ignore-platform-reqs` — the Composer image has none of the extensions; the runtime image has them all and the test suite runs in that image.
- 2026-11-15 — `COOKIE_DOMAIN` was added to `apps/lokakode/.env` and `apps/portal/.env` on this server (value `.lokandita.com`, not a secret) — the shared package needs it to re-send the session cookie after a touch.
- 2026-11-15 — The shared package re-sends `lokandita_sid` after a touch — without it the cookie would die 12 hours after the last visit to LokaAuth while the server-side session was still alive, and "Tetap masuk" would be a lie.
- 2026-11-15 — If LokaAuth cannot be reached, Keluar in a client app answers 502 and says plainly that the user is still logged in — v1 reported a logout that had not happened.
- 2026-11-15 — CSRF tokens are stable for 12 hours instead of regenerated per request — regeneration breaks the second tab and the background session ping.
- 2026-11-15 — HTML attributes are escaped with plain `esc()` inside double quotes — the `attr` context turns every URL into numeric entities, which is valid but unreadable in the page source.
- 2026-11-15 — The Portal has no logo yet: the branding archive holds only LokaAuth and LokaKode — to settle in stage 11.
- 2026-11-15 — `/internal/password-reset` refuses targets that are not mahasiswa — a bug or break-in in a client app must not be able to reset a lecturer or a superadmin.
- 2026-11-15 — `touch`, `users/{id}` and `lookup` are not written to `audit_log`, only to the container log — a touch every 5 minutes per session would bury the audit page; every denial and every state change is audited.
- 2026-11-15 — The first superadmin is created by `docker exec -it auth php spark akun:superadmin`; the temporary password is printed once in that terminal — there is no web registration and no default account.
- 2026-11-15 — A TOTP code is accepted once: used codes are remembered in Redis for 2 minutes; clock tolerance is 15 seconds — a code read over a shoulder cannot be replayed.
- 2026-11-15 — The QR code for enrolment is an inline SVG made by `bacon/bacon-qr-code` — no image extension, no external service sees the secret.
- 2026-11-15 — The TOTP secret is encrypted with libsodium `secretbox` under `MFA_ENCRYPTION_KEY`; backup codes are 10 random characters stored as SHA-256 — random codes need no slow hash.
- 2026-11-15 — A wrong TOTP or backup code counts as a login failure for the lockout — otherwise the second step could be guessed without limit.
- 2026-11-15 — The account menu and toasts use a small hand-written script without Alpine.js — standard Alpine needs `unsafe-eval`, which the CSP forbids; the menu is a native `<details>` and works without JavaScript.
- 2026-11-15 — Security headers and the CSP nonce come from `Lokandita\Auth\Filters\SecurityHeaders`, not CI4's CSP class — forty readable lines, identical in the three apps.
- 2026-11-15 — `form-action` in the CSP lists every Lokandita host — browsers also apply it to the redirect after a form post (login → `next`, Keluar → LokaAuth).
- 2026-11-15 — `/healthz` is exempt from the CSRF filter — the filter sets a `Secure` cookie and the health check runs over plain HTTP inside the container; found by the tests, it would have failed every deploy.
- 2026-11-15 — Lockout counter: failures older than 15 minutes are forgotten before the first lock; once locked, the counter survives until a successful login or 24 quiet hours — otherwise waiting out one lock would reset the progression.
- 2026-11-15 — Attempts made while an account is locked are recorded but neither count nor extend the lock — an attacker must not be able to keep a student locked out forever.
- 2026-11-15 — Common-password list: the 10-character-and-longer entries of SecLists "10k most common" plus Indonesian and Lokandita-specific entries, and rules for repeated characters and digit runs (`apps/auth/app/Data/kata-sandi-umum.txt`).
- 2026-11-15 — Until MFA exists (step 4) a superadmin cannot obtain a session at all — never a superadmin session without TOTP, even between commits.
- 2026-11-15 — `tes.sh` proves a migration ran by looking for the `migrations` table — `spark migrate` exits 0 even when it cannot connect.
- 2026-11-15 — `DB_DSN` is parsed by `Lokandita\Auth\Dsn` into plain fields — CI4's DSN parser passes the port as a string and mysqli refuses it; found by the first harness run, stage 4 never connected through CI4.
- 2026-11-15 — Tests are black-box: real HTTP to a second LokaAuth (`auth-tes`) on `identity_test`, plus direct SQL for setup and assertions — in-process feature tests would not exercise cookies, headers and container networking, which is where v1 failed.
- 2026-11-15 — The test image is the production Dockerfile with dev dependencies added (`COMPOSER_DEV=`), tag `:tes` — the code under test is built the same way as the code that is deployed.
- 2026-11-15 — PHPUnit fails on skipped and incomplete tests — a skipped test must not look like a pass.
- 2026-11-15 — Backups are not encrypted and stay on the server disk (`/srv/lokandita-data/backups`, mode 700), run by the `deploy` user's crontab at 02:00 WIB — owner accepted no off-server copy for now; a crontab needs nothing under `/etc`.
- 2026-11-15 — Example tests shipped with the CI4 starter were deleted — they pass without testing anything of ours.
- 2026-11-15 — `deploy.sh` removes older images of the app it just deployed — rollback is `git checkout` plus deploy, and old images only fill the disk.
- 2026-11-15 — `deploy.sh` refuses a dirty working tree — otherwise `/healthz` could report a commit that is not what is running.
- 2026-11-15 — App images carry a moving tag `aktif` next to the commit tag — Compose can then start any service without knowing commit hashes; the `/healthz` check is what proves the version.
- 2026-11-15 — Maintenance is a per-host flag file read by Caddy on each request, default on — apps can be opened one at a time in later stages without editing the Caddyfile; a fresh server exposes nothing.
- 2026-11-15 — The maintenance page is static HTML served by Caddy with Indonesian, English and Arabic text inline — owner-approved exception to the language-file rule, because no CI4 app is involved.
- 2026-11-15 — HSTS is sent without `includeSubDomains` and without `preload` — preload is hard to undo and future subdomains are not built yet.
- 2026-11-15 — Certificates were first requested from the Let's Encrypt staging CA, then production — a mistake in DNS or ports would otherwise burn the production rate limit.
- 2026-11-15 — Redis requires a password although it is only on the `data` network and loopback — a second barrier costs nothing.
- 2026-11-15 — `identity_reader` is created now without any right; grants arrive with the views in stage 5 — the password is fixed in every `.env` from the start and a grant on a missing view is impossible.
- 2026-11-15 — Startup validation takes its list from `.env.example` — one list instead of three that can drift.
- 2026-11-15 — Env check and `/healthz` controller live in `packages/lokandita-auth` — they are identical in all three apps.
- 2026-11-15 — Composer project names are `lokandita/app-<name>` — `lokandita/auth` is the shared package's name.
- 2026-11-15 — One `infra/docker/app.Dockerfile` for the three apps, build context = repository root — the path package must be inside the context.
- 2026-11-15 — App image is `php:8.3.36-apache` with `FallbackResource`, listening on 8080 as `www-data` — one process, no extra web server container, nothing unusual to maintain.
- 2026-11-15 — Image versions are pinned: MySQL 8.4.13, Redis 7.4.12, Caddy 2.11.9, Composer 2.11.2, phpredis 6.2.0, CodeIgniter 4.7.6 (lock file) — upgrades should be deliberate.
